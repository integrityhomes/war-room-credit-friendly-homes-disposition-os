## Whole-app interpretation and known gaps

The full existing suite still exercises all previously covered business services. The new scenarios close the prior authenticated-page gaps; that is surface execution coverage, not exhaustive branch or remote-backend coverage. Original CFH marketing pages remain included: optimizer, acquisition/reactivation, creative rotation, conversion, vacant escalation, attribution, channel cadence, tracking links, short video, classifieds, paid traffic, email/SMS, owned web, manual Facebook groups and Marketplace.

My Work remains the active workspace; its dispatch queue contains campaign work, not a replacement canonical task system. A shared read-only projection now displays the exact canonical CRM task records in My Work, Operations, Team Health and Workload Balance. Rescheduling, reassignment, notes and completion use the existing canonical executor and embedded audit history. No task copies are stored in dispatches. Team Health includes internal task counts when the assignee uniquely matches the existing registry; unresolved registry matches are explicitly flagged. Dispatch rebalancing remains dispatch-only and is labeled accordingly. Internal tasks are reassigned through Command Bot.

Priority questions now use verified communications, approvals, blockers, due tasks, source changes and stale evidence to recommend a ranked review order. The first item supplies the explicitly stated follow-up context. The real-page regression creates one synthetic follow-up without inventing an unspecified due date, then verifies every task update across all four work surfaces. The registry also has no dedicated team-health, workload-balance, coverage-exception or marketing-attribution tools. Do not claim these Command Bot capabilities merely because their screens render.

Remote Supabase/edge-function and provider decisions are mocked contracts. A Deno runtime was not available during this audit; no new runtime, service or credentials were installed. Local rendering does not establish end-to-end validation of those remote services.

## Serialized import rule

Current-inventory import is single-worker only. The existing OS file lock rejects a second simultaneous attempt before canonical I/O. A concurrent-thread test holds the first worker inside a fake upload and proves the second is rejected; exactly 29 synthetic properties remain. Independent subprocess/distributed-worker behavior remains WARNING until a guarded child adapter proves it. No live entry point is activated.

## Permanent gate policy

Run the full suite under the safety wall. Failures fail the gate. The two functional warnings are ordinary regression assertions now; a regression fails the gate. A zero-failure run is not a declaration that every cross-module workflow is complete. The simulator is suitable as an ongoing regression gate, but these integration gaps and remote-service limits must remain visible.
